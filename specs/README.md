# WireGuard（HarmonyOS）功能规格索引

本目录存放**用户视角**的功能规格：每个功能一份 spec，描述「功能是什么、用户怎么操作、
看到什么、边界情况如何表现」，**只写需求与功能设计，不含技术方案**（架构、API、算法、
存储方式等实现内容见 `docs/decisions/`）。

规格基线：**上游 WireGuard-Android**（`~/LibSource/WireGuard-Android`，tag
`1.0.20260315-1-ge7b3a3c1`）的用户可感知行为；与上游的差异在每份 spec 末尾
「与上游的差异」一节显式列出。

## 通用约束

- **设备形态**：仅 phone。全部页面以竖屏为主要形态；折叠屏**外屏（小正方形窗口）为验收目标**
  （见 [cover-screen.md](cover-screen.md)）；横屏 / 折叠屏展开态不单独验收，
  但页面旋转 / 折叠切换不得丢失用户已输入 / 已浏览的状态。
- **无障碍**：本期不做专门适配，仅保证系统默认字号下关键文案不截断。
- **升级兼容**：应用升级不丢失已保存的隧道；若历史数据无法读取，该隧道不出现在
  列表中（不崩溃），并在日志中记录。
- **公共术语——隧道名称规则**：仅允许 ASCII 字母、数字及 `_ = + . -`，长度 1–15 字符；
  重名判定按**完全一致（区分大小写）**。导入、编辑器、命名对话框、列表排序均引用本规则。
- **错误提示包装规则**：面向用户的操作失败信息统一为「<操作>失败：<原因>」
  （如「无法导入隧道：<原因>」）；对话框内的行内错误只显示 `<原因>`。
  各 spec 中的文案表列出 `<原因>` 部分的固定文案。
- **单一取舍真源**：上游功能的取舍结论以本文件「功能取舍总表」为准，
  各功能 spec 只引用、不重复维护理由。
- **有意修正的上游缺陷**：各 spec「与上游的差异」小节会列出本项目有意不继承的
  上游 bug（如导入失败原因丢失、MTU 报错字段错标、删除失败计数恒 0 等），
  实现与验收以修正后行为为准。

## 功能取舍总表

上游有、本项目的取舍（含裁剪/暂缓与「保留但行为不同」）：

| 上游功能 | 处理 | 理由 |
|---|---|---|
| 内核模块加速 | ❌ 裁剪 | 平台不提供内核级加速能力（无内核模块、无 root） |
| 安装 `wg`/`wg-quick` 命令行工具 | ❌ 裁剪 | 平台无 root、无 shell 工具安装途径 |
| 同时开启多条隧道 | ❌ 裁剪 | 系统同时只允许一条 VPN 连接（系统行为） |
| 快速设置磁贴 | ⏸️ 暂缓 | 平台无对应系统磁贴；后续可评估服务卡片 |
| 外部应用远程控制隧道 | ⏸️ 暂缓 | 平台外部唤起机制需单独安全评估后再定 |
| 应用内更新器 | ❌ 裁剪 | 分发走应用市场，不内置更新器 |
| 捐赠入口 | ❌ 裁剪 | 与平台分发政策相关，不内置 |
| 大屏/TV 界面 | ❌ 裁剪 | 设备形态仅 phone |
| 首次启动引导/隐私政策页 | ❌ 裁剪 | 由应用市场流程承担 |
| 连接后的常驻通知/快捷断开入口 | ❌ 裁剪 | 依赖系统 VPN 标志与系统设置入口，应用不提供额外常驻通知 |
| 启动自动恢复隧道 | ❌ 裁剪 | 上游有三种自动恢复（开机 / 进程启动 / 系统级始终开启），平台普通应用均无对应能力，且自动重连会触发系统授权框（见 [tunnel-connection.md](tunnel-connection.md)） |
| 应用过滤（按应用生效/不生效） | ✅ 保留 | 平台 VPN 能力支持按应用设置生效/不生效名单 |
| 查看私钥/导出配置前锁屏认证 | ✅ 保留 | 平台支持生物识别与锁屏凭证 |
| 编辑页防截屏 | ✅ 保留 | 平台提供防截屏能力 |
| 暗色主题开关 | ✅ 保留（行为不同） | 上游在新版本系统上已移除该开关、强制跟随系统；本项目保留手动开关（关 = 跟随系统，开 = 暗色） |

## 迭代规则

- 任何功能新增/变更，**先改对应 spec 与 `handbook/` 说明书，再改代码**。
- 代码行为与 spec 冲突时以 spec 为准；若 spec 本身有误，先修 spec。
- spec 只写需求与功能设计；实现方案一律写入 `docs/decisions/`。
- 每份 spec 末尾的「待验证事项」需要在真机验证后回写确认结果。
