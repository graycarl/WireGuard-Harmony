# 连接与断开

## 概述

用户通过隧道列表项或详情页的开关连接/断开隧道。连接的本质是创建一个系统级
VPN 虚拟网卡并在后台运行 WireGuard 协议。本 spec 描述用户在开关过程中可感知的
全部行为：系统授权、状态反馈、错误提示，以及应用/系统状态变化时的状态一致性。

## 入口

- 隧道列表项的开关；
- 隧道详情页的开关。

## 行为规则

### 开启隧道

1. 用户把开关拨到「开」。操作期间开关临时禁用（保持原视觉，无独立「连接中」图形态），
   直到连接结果确定。
2. **系统 VPN 授权**：建立 VPN 连接时，系统弹出 VPN 授权框：
   - 用户同意 → 继续建立连接；
   - 用户拒绝/取消 → 视为结果确定（开关恢复原位），提示
     **「建立连接时出错：用户未授权 VPN 服务」**；之后再次拨动开关会重新弹出授权框。
   - 系统授权框在首次同意后是否每次连接都弹出，待真机验证（见待验证事项）。
3. 建立成功：开关变为「开」并保持，系统状态栏出现 VPN 标志。
4. 建立失败：开关弹回原位，底部提示 **「建立连接时出错：<原因>」**。

### 关闭隧道

1. 用户把开关拨到「关」，隧道断开，开关保持在「关」，系统 VPN 标志消失。
2. 关闭失败（罕见）：开关弹回原位，提示「断开连接时出错：<原因>」。

### 切换隧道（一条已连接时开启另一条）

系统同时只允许一条 VPN 连接。当隧道 A 已连接、用户拨开隧道 B 的开关时：

1. 切换过程中 A、B 两个开关均临时禁用；应用自动**先断开 A，再连接 B**
   （不要求用户先手动关 A）。
2. B 建立成功：A 显示为「关」并恢复可用，B 为「开」。
3. B 建立失败：应用**自动把 A 恢复为已连接**（A 的开关先关后开），
   B 的开关弹回原位并提示「建立连接时出错：<原因>」。
   （与上游一致：上游在切换失败时会回滚并重新拉起原隧道。）

### 状态一致性

- 开关显示的状态永远以**系统侧真实 VPN 状态**为准，而不是用户的最后一次操作意图。
- 以下情况 UI 状态自动跟随纠正，无需用户操作：
  - 用户在系统设置中手动关闭了本应用的 VPN；
  - 应用进程被系统结束导致 VPN 断开（是否如此依赖系统行为，见待验证事项）；
  - 其他 VPN 应用抢占了 VPN 通道（此时本应用隧道断开；反过来，本应用发起连接
    会顶掉其他 VPN 应用，这由系统处理）。
- 从其他页面返回列表/详情页时，开关状态刷新为最新真实状态
  （上游无页面返回刷新机制，本项目新增）。

### 网络变化

- 已建立的连接在**网络切换**（如 Wi-Fi ↔ 移动数据）时保持，UI 状态不变
  （WireGuard 协议自带对端漫游能力）。
- **无网络/飞行模式**下拨开开关：按建立失败处理，开关弹回原位，
  提示「建立连接时出错：<原因>」（原因为系统返回的网络错误）。
- 网络恢复后不自动重连，需用户手动开启。

### 修改已连接隧道的配置

- 在编辑器中保存正在连接的隧道：**断开并以新配置立即重连**（存在短暂中断），
  UI 上开关保持「已连接」；重连失败则以真实状态呈现并提示原因。

### 对已连接隧道改名

- 先断开 → 改名 → 以新名称自动重新连接。
- 失败处理：
  - 改名（含其中的断开/重连）失败：提示「无法重命名隧道：<底层原因>」，
    隧道保持断开、以实际生效的名称显示，开关按真实状态呈现，不自动重试；
  - 改名成功但随后的配置保存失败：提示「无法保存 '<新名称>' 的配置：<原因>」。

### 删除隧道

- **单条（列表多选删除）**：先断开连接再删除；断开失败则**不执行该项删除**，
  提示沿用批量删除文案（见下）；删除失败则恢复原连接、隧道保留在列表中。
- **批量删除中含已连接项**：已连接项先断开；断开失败的项计入失败数，
  **整批继续处理其余项**，结果提示为「无法删除 N 项：<原因>」
  （N = 断开失败 + 删除失败的项数）。

### 并发操作

- 连接/断开过程中，同一隧道的编辑、删除操作不被阻塞；最终状态以系统真实结果为准。

### 配置不完整时连接

- 配置缺少本机地址或路由段（含零个 Peer）时**不做额外拦截**，直接尝试建立；
  连接可能成功但无可用网络（与上游一致）。

### 启动自动恢复（不提供）

- 上游支持三种自动恢复：设备开机后恢复、应用进程启动时恢复、以及系统级
  「始终开启的 VPN」被系统拉起时恢复。
- 本项目**不提供任何形式的开机/启动自动重连**（理由见 [README.md](README.md) 裁剪总表）：
  用户打开应用后所有隧道均显示为断开，需手动开启。

## 错误原因文案（用户可见）

| 场景 | 文案 |
|---|---|
| 用户未授权 VPN | 「用户未授权 VPN 服务」 |
| 无法创建虚拟网卡 | 「无法创建 tun 设备」 |
| 无法启动系统 VPN 服务 | 「无法启动 VPN 服务」 |
| 隧道引擎启动失败 | 「无法开启隧道（错误码 <N>）」（内核/工具相关错误已裁剪，见差异） |
| 对端域名解析失败 | 「无法解析 DNS 主机名：'<主机名>'」 |
| 隧道没有保存配置就尝试连接 | 「尝试在无配置情况下建立连接」 |
| 已有其他 VPN 连接占用 | 「建立连接时出错：系统同时只允许一条 VPN 连接，请先断开其他 VPN 后重试」（本项目新增文案，上游无对应提示） |
| 其他未知错误 | 「未知的 '<描述>' 错误」（`<描述>` 为系统返回的错误描述原文） |

## 与上游的差异

| 项 | 上游（Android） | 本项目（HarmonyOS） |
|---|---|---|
| 多隧道并行 | 可选开启 | 不支持（系统限制一条 VPN） |
| 开机/启动自动恢复 | 支持（开机 / 进程启动 / 系统级始终开启） | 不支持，需手动开启 |
| VPN 授权框 | 系统弹框；拒绝后报错提示 | 首次连接弹出；是否每次弹出待真机验证；拒绝后报错提示（同上游） |
| 页面返回时刷新开关状态 | 无（靠服务回调） | 有（新增） |
| 「已有其他 VPN 连接」提示 | 无 | 有（新增文案） |
| 「无法启动 VPN 服务」文案 | 「无法启动 Android VPN 服务」 | 「无法启动 VPN 服务」（去掉平台名） |
| 内核/命令行工具相关错误 | 有（内核模块、wg-quick 等） | 已裁剪（本项目无这些能力） |
| 切换隧道失败后原隧道 | 自动回滚并恢复 | 同上游（自动恢复 A） |

## 待验证事项

- 系统 VPN 授权在首次同意后，再次连接是否仍会弹授权框。
- 应用进程被杀后系统断开 VPN 的实际表现与时延。
- 系统设置中关闭 VPN 后，应用能否拿到状态变更通知（决定 UI 纠正的及时性）。
