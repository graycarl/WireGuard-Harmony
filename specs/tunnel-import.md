# 导入隧道

## 概述

用户可以通过四种方式把已有的 WireGuard 配置变成应用里的隧道：
从文件导入单个 `.conf`、从 `.zip` 压缩包批量导入、相机扫描二维码、
从相册图片中识别二维码。导入过程中应用负责解析校验配置（格式见
[config-format.md](config-format.md)），并用清晰的提示告知成功、部分成功或失败。

## 入口

隧道列表页「+」按钮 → 半模态面板中的「导入配置或压缩包」或「扫描二维码」。

## 方式一：导入 `.conf` 文件

1. 系统文件选择界面打开，用户选择一个 `.conf` 文件。
2. 应用以**文件名（去掉 `.conf` 扩展名、去掉目录路径）作为隧道名称**，解析文件内容。
3. 解析成功且名称未冲突：直接创建隧道，提示 **「导入了 '<名称>'」**。
4. 失败则提示错误（见「错误与边界情况」）。

**派生名称不合法时的处理**：文件名派生出的名称若不符合隧道名称规则
（超过 15 字符、含非法字符，如中文/空格，见 [tunnel-editor.md](tunnel-editor.md)），
单文件导入时弹出**隧道命名对话框**（预填清理后的名称）让用户确认/修正，
而不是直接失败（本项优于上游，见「与上游的差异」）。

## 方式二：导入 `.zip` 压缩包（批量）

1. 用户选择一个 `.zip` 文件。
2. 应用遍历压缩包内所有条目，**只处理扩展名为 `.conf` 的文件**（忽略目录、
   忽略其他类型文件）；每个 `.conf` 的文件名（去路径、去扩展名）作为隧道名称。
3. 每个配置独立解析、独立创建，**互不影响**：单个失败不阻止其余导入。
   条目数量无上限，逐条处理。
4. 全部处理完后显示汇总提示：
   - 只导入成功 1 条且无失败：「导入了 '<名称>'」；
   - 多条全部成功：「导入了 N 个隧道」；
   - 部分成功：「导入了 M 项中的 N 项，<最后一条失败原因>」（原因保留「无法导入隧道：」前缀，
     即**始终显示失败原因**，见「与上游的差异」）；
   - 全部失败：显示按条目顺序**最后一条**失败原因「无法导入隧道：<原因>」
     （0 成功时也必须给出原因，见「与上游的差异」）。
5. zip 中派生名称非法的条目：该条失败（为避免逐条弹窗打断，不弹命名对话框），
   提示「无法导入隧道：名称无效」，计入失败数。

## 方式三：相机扫描二维码

1. 打开扫码界面，对准包含 wg-quick 配置文本的二维码。
   应用在**进入系统扫码界面之前**的应用内页面展示提示：
   「提示：使用命令 `qrencode -t ansiutf8 < tunnel.conf` 生成二维码」
   （平台事实：系统默认扫码界面不允许叠加应用自定义文案，故提示改由应用内页面承载，
   见「与上游的差异」）。
2. 识别成功后，先**校验**二维码中的配置文本：
   - 校验失败：提示「无法导入隧道：<解析错误>」，不继续；
   - 校验通过：弹出**隧道命名对话框**（见下）。
3. 设备无摄像头、或相机不可用时，「+」面板中不显示此入口。

## 方式四：从图片识别二维码

在系统文件选择界面中选择的是**图片文件**时（按文件类型判定，优先于扩展名判定），
应用自动尝试识别图中的二维码：

1. 识别出二维码且内容可解析：进入隧道命名对话框（同方式三）。
2. 识别不出二维码：提示 **「无法导入隧道：图片中未发现二维码」**。
3. 识别出二维码但内容校验失败：提示「无法导入隧道：二维码校验失败」。
4. 图片本身无法解码：提示「无法导入隧道：<解码错误原因>」。

**文件类型判定顺序**：图片类型 → 方式四；扩展名 `.conf` → 方式一；
扩展名 `.zip` → 方式二；其余 → 报错「仅支持 .conf、.zip 或图片文件」。

## 隧道命名对话框

- 标题：「从二维码导入隧道」。
- 一个名称输入框（输入规则同隧道名称规则，见 [tunnel-editor.md](tunnel-editor.md)）。
- 按钮：「创建隧道」「取消」。
- 名称非法或重名时，在输入框下方显示错误（「名称无效」或「名称 '<名称>' 已存在」），
  不关闭对话框，用户可修改后重试。
- 创建成功后对话框关闭，新隧道出现在列表中。

## 错误与边界情况

| 场景 | 表现 |
|---|---|
| 文件类型不属于 `.conf` / `.zip` / 图片 | 提示「仅支持 .conf、.zip 或图片文件」 |
| `.conf` 内容无法解析 | 提示「无法导入隧道：<解析错误>」，解析错误含位置与原因（见 [config-format.md](config-format.md)） |
| zip 中没有任何 `.conf` | 提示「无法导入隧道：未找到配置」 |
| 隧道名称与已有隧道重复 | 该条失败（批量导入时计入失败数），提示「无法导入隧道：名称 '<名称>' 已存在」 |
| 单文件派生名称非法 | 弹命名对话框，预填清理后名称供用户确认/修正 |
| zip 内条目名称非法 | 该条失败，提示「无法导入隧道：名称无效」 |
| 二维码内容不是合法配置 | 提示「无法导入隧道：<解析错误>」，不弹命名对话框 |
| 用户取消文件选择/扫码 | 无任何提示，回到列表页 |

## 与上游的差异

- 上游用系统内容选择器选文件；本项目用系统文件选择界面，交互形态随平台惯例，
  行为要求不变。
- 上游使用外部扫码实现；本项目扫码界面按平台能力实现，用户可感知行为一致
  （对准即识别、无提示音要求）。
- **扫码提示文案的展示位置**：平台默认扫码界面不支持叠加自定义文案，本项目把
  「`qrencode` 生成二维码」提示放在进入扫码前的应用内页面（内容不变）。
- 上游扫码支持横竖屏；本项目扫码界面固定竖屏。
- **导入失败原因丢失**：只要存在至少 1 个成功项，上游就不再显示任何失败原因
  （仅显示「导入了 M 项中的 N 项」）；0 成功且 ≥2 失败时也只显示「导入了 N 项中的 0 项」
  （上游 bug）。本项目修正为**始终显示失败原因**。
- **单文件派生名称非法**：上游直接失败并提示「名称无效」；本项目改为弹命名对话框
  让用户现场命名。
- **文件扩展名错误的提示**：上游文案为「扩展名必须为 .conf 或 .zip」（未提图片），
  本项目文案改为「仅支持 .conf、.zip 或图片文件」，与实际支持的图片二维码路径一致。

## 待验证事项

- 系统文件选择界面能否按扩展名过滤 `.conf`/`.zip`，以及能否拿到文件显示名
  （用于派生隧道名称）；若拿不到显示名，则改用「导入的隧道 N」并弹命名对话框
  请用户确认（该处理方式已在正文定案，仅平台能力待验证）。
- 相机不可用（无摄像头或调用失败）时能否可靠判定以隐藏扫码入口
  （现实现：系统能力标记 + 相机管理器可用摄像头数，两者任一不满足即隐藏）。
- 无扩展名文件的类型嗅探（zip 魔数 / `[Interface]` 内容 / 二维码识别）与
  zip 解包目录结构、用户取消保存的返回形态，均为真机验证项。
