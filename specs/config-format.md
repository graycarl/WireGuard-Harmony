# 配置文件格式（wg-quick）与校验规则

## 概述

本 spec 定义应用导入、编辑、导出隧道时所遵循的配置文件格式契约
（wg-quick `.conf` 文本），以及解析失败时用户可见的错误描述方式。
导入（[tunnel-import.md](tunnel-import.md)）与编辑器保存
（[tunnel-editor.md](tunnel-editor.md)）共用同一套规则；导出的 zip 中每个
`.conf` 文件均按本格式的标准序列化输出。

## 文件格式

- UTF-8 纯文本，由若干**节**组成：一个或多个 `[Interface]` 节（多个时合并）
  和零个或多个 `[Peer]` 节。
- 节内每行一条 `键 = 值` 属性（键不区分大小写，`=` 两侧空白忽略，**值不得为空**）。
- 行内任意位置出现 `#`，其后到行尾均视为注释被截断（因此值中不能含 `#`）；空行忽略。
- 第一个节标题之前仅允许空行与注释行，出现其他任何内容、或出现未知节标题，均为格式错误。
- 列表型值用英文逗号分隔（逗号两侧空白忽略）。
- 同一节内同一键重复出现时：标量键（如 `PrivateKey`）以最后出现的值为准，
  列表键（如 `Address`/`DNS`/`AllowedIPs`）逐行累加（与上游一致）。
- 值的首个字符不能是空白（否则视为语法错误）；值**尾部**的空白不被忽略
  （与上游一致），因此值末尾带空格的行可能解析失败。
- 不在下两表中的任何键（包括上游 wg-quick 的桌面扩展键 `Table`、`PreUp`、`PostUp`、
  `PreDown`、`PostDown`、`SaveConfig`、`FwMark` 等）一律按**未知属性**报错拒绝——
  与上游 Android 客户端行为一致。

### `[Interface]` 节属性

| 键 | 必填 | 规则 |
|---|---|---|
| `PrivateKey` | ✅ | base64 编码的 32 字节私钥（44 字符，末位 `=`） |
| `Address` | 否 | 逗号分隔的 IP 网络（CIDR），支持 IPv4/IPv6，如 `10.0.0.2/32` |
| `ListenPort` | 否 | UDP 端口，0–65535；`0` 或缺省表示随机 |
| `DNS` | 否 | 逗号分隔；能解析为 IP 地址的条目是 DNS 服务器，符合主机名规则的条目视为 DNS 搜索域名；两者都不是的条目按解析错误处理（报在 DNS 字段） |
| `MTU` | 否 | 非负整数；`0` 或缺省表示自动 |
| `ExcludedApplications` | 否 | 逗号分隔的应用标识（与 `IncludedApplications` 互斥） |
| `IncludedApplications` | 否 | 逗号分隔的应用标识（与 `ExcludedApplications` 互斥） |

### `[Peer]` 节属性

| 键 | 必填 | 规则 |
|---|---|---|
| `PublicKey` | ✅ | base64 编码的 32 字节对端公钥 |
| `PresharedKey` | 否 | base64 编码的 32 字节预共享密钥 |
| `AllowedIPs` | 否 | 逗号分隔的 IP 网络（CIDR） |
| `Endpoint` | 否 | `主机:端口`，主机可为 IPv4、`[IPv6]` 或域名；端口 0–65535（`0` 语法上被接受，但语义上不可达，与上游一致不做额外拦截）；整串中不允许出现 `/ ? #` 字符 |
| `PersistentKeepalive` | 否 | 0–65535 的整数秒；`0` 或缺省表示关闭 |

### 密钥编码

- 配置文件与编辑器中，密钥**仅接受 base64**（44 字符，对应 32 字节，末位 `=`）。
- 长度不符报「密钥长度错误」；含 base64 字符集以外的字符报「密钥中含错误字符」。

## 错误描述方式（用户可见）

解析失败时，错误信息由 **位置 + 原因** 组成，例如：
「在 本地 的 私钥 字段发生了 密钥长度错误 的问题」。

- **位置**：`本地（Interface）` / `远程（Peer）` 的某个字段名；
  节级错误直接显示节名；文件级错误显示整体。
- **原因**：

| 原因 | 含义 | 附加说明文案（按出错字段追加） |
|---|---|---|
| 语法错误 | 行不符合 `键 = 值` 形式（含值为空） | — |
| 未知节 | 节标题不是 `[Interface]`/`[Peer]`，或节前有内容 | — |
| 未知属性 | 节内出现不支持的键 | — |
| 缺失节 | 整个文件没有 `[Interface]` 节 | — |
| 缺失属性 | 必填属性缺失（`PrivateKey`/`PublicKey`） | — |
| 密钥长度错误 | 密钥长度不是 44 个字符（32 字节） | 「WireGuard 的 Base64 密钥长度必须为 44 个字符（32 字节）」 |
| 密钥中含错误字符 | 密钥含 base64 字符集以外的字符 | — |
| 数字无效 | 应为整数的位置不是整数 | — |
| 数值无效 | 数值语义非法或越界 | 监听端口：「必须为有效的 UDP 端口号」；保活间隔：「必须为 0–65535 的整数」；MTU：「必须为非负整数」 |
| 无法解析…… | IP 地址 / IP 网络 / 对端 字符串无法解析 | 「无法解析 IP 地址 'xxx'」等 |

## 导出序列化

- 导出的 `.conf` 使用上述标准格式：`[Interface]` 在前、各 `[Peer]` 在后，
  属性按固定顺序、键名使用标准大小写（如 `PrivateKey`），列表用 `, ` 连接。
- `DNS` 行：只要 DNS 服务器或搜索域名任一非空即输出（见「与上游的差异」第 5 条）。
- 导出内容包含**完整私钥**——因此导出前必须通过锁屏认证
  （见 [privacy-security.md](privacy-security.md)）。
- 导出不中断正在连接的隧道；导出内容为**最新已保存**的配置。

## 与上游的差异（有意修正的上游缺陷）

解析行为整体与上游 `tunnel` 库逐条对齐；以下是本项目**有意不同**的点：

1. **MTU 越界报错位置**：上游把负 MTU 的报错字段错标为「监听端口」（上游 bug），
   本项目修正为报在 MTU 字段。
2. **应用过滤互斥报错**：上游对「同时配置 Included/ExcludedApplications」抛出
   「密钥无效」（易被误读为密钥问题），本项目使用明确表述「应用过滤的两种模式
   不能同时设置」。
3. **Endpoint 中的 `@`**：上游未禁止 `@`，含 `@` 的输入会被静默接受并改变实际
   连接的主机（如 `foo@bar.com:51820` 实际连接的是 `bar.com`）；本项目将其作为
   「无法解析对端」报错。
4. **错误文案本地化**：上游错误中的节名/字段名使用英文标识符
   （如「在 Interface 的 PrivateKey 字段……」），本项目使用本地化名称
   （如「在 本地 的 私钥 字段……」）。
5. **导出丢失搜索域名**：上游导出时若只配置了搜索域名（无 DNS 服务器）会丢失它们，
   本项目修正为任一非空即输出 `DNS` 行。
6. **数值附加说明文案**：上游对保活间隔/MTU 的附加说明写作「正整数」，但实际允许
   `0`（表示关闭/自动），本项目文案修正为「0–65535 的整数」/「非负整数」。
