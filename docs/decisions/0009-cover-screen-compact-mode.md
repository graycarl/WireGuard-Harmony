# 0009 · 折叠屏外屏适配：窗口尺寸驱动的紧凑布局

- 状态：**已决定**（2026）
- 关联：[specs/cover-screen.md](../specs/cover-screen.md)

## 背景

阔折叠设备（如华为 Pura X）的外屏是小尺寸、接近正方形的显示区域（约 980×980px，
按密度折算约 356–392vp 见方——以真机实测为准，见 spec 待验证事项）。现有界面
全部按常规手机竖屏（约 360×640vp 以上）设计，标题栏 / 行高 / 边距偏大，
在外屏上单屏信息量过低。需要让应用在小窗口下自动切换为紧凑布局，且常规竖屏
不受影响。

## 备选方案

1. **官方「一多」断点系统（mediaquery + BreakpointSystem）**：按窗口宽度分
   xs/sm/md/lg 档，配合监听回调。——否决：本项目只有「常规 / 紧凑」两档需求，
   且区分外屏的关键维度是**高度**（外屏宽度 ~360-390vp 与窄屏手机接近，高度才
   是显著差异），宽度断点系统解决不了主问题，引入整套断点设施过重。
2. **监听折叠状态（display 折叠状态变化）**：按设备物理形态切换布局。
   ——否决：依赖具体设备类型，覆盖不了「手机横屏 / 悬浮小窗」这些同样矮小的窗口；
   且折叠状态接口无法在本地单测验证，与决策 0007 的测试分层冲突。
3. **窗口尺寸驱动（选定）**：在根组件测量应用窗口的宽高（vp），
   由纯函数判定是否进入紧凑模式，经可观察单例分发给各页面。

## 决策内容

1. **判定规则（纯逻辑，进本地单测）**：`util/ScreenMode.ets`
   - `isCompactWindow(widthVp, heightVp)`：**高度 < 560vp 或 宽度 < 360vp** 即紧凑。
     - Pura X 外屏约 356–392vp 见方 → 触发；
     - 常规手机竖屏高度 ≥ 640vp、宽度 ≥ 360vp → 不触发；
     - 手机横屏（高约 360vp）与悬浮小窗同样触发——这些场景同样受益于紧凑布局，
       与 spec「小尺寸窗口自动进入紧凑布局」一致。
   - 尺寸档位集中在 `Dimens` 类（标题栏高 56→46、行高 56→46、页面边距 16→10、
     详情标签列宽 120→88、编辑器标签列宽 92→64、FAB 56→48 等），
     页面不各自散落魔法数。
2. **状态分发**：`components/ScreenState.ets` 导出 `@ObservedV2` 单例
   `screenState`（@Trace compact），页面 / 组件直接读取、框架按属性级依赖刷新
   ——与 `ListSelection` 同一模式（AGENTS.md 已知坑：@Param + ForEach 复用
   不刷新，故不能靠父组件透传）。判定逻辑保持纯函数，装饰器单例不进本地单测。
3. **测量点唯一**：`Index.ets` 的 Navigation 根组件 `onAreaChange`（vp 单位）→
   `screenState.update(w, h)`。一处测量覆盖全应用（含 NavDestination 子页），
   且天然覆盖折叠 / 展开、横竖屏、小窗缩放等一切窗口变化，无需监听折叠状态。
4. **module.json5**：EntryAbility 显式声明
   `"supportWindowMode": ["fullscreen", "split", "floating"]`（与缺省值相同，
   显式写出以防将来缺省变化）、`"minWindowWidth": 320`、`"minWindowHeight": 240`——
   向系统声明本应用支持收缩到小窗口（含外屏），是外屏可用性的必要条件之一。
5. **折叠 / 展开状态保持**：不额外处理——路由栈与页面状态由 Navigation 持有，
   窗口变化不重建 Ability；spec 的「切换不丢草稿」由现有实现保证。

## 后果

- 正面：紧凑判定 100% 本地单测覆盖；一处测量、全局生效；常规竖屏零变化
  （阈值不触发）；同时惠及横屏与小窗。
- 负面：紧凑模式的尺寸表是手工调参，外屏实际 vp 若与估算偏差大，阈值可能要
  微调 → 验证后回写本文件与 spec 待验证事项。
- 限制：不处理系统弹窗（VPN 授权 / 认证）在外屏上的显示（系统绘制，应用不可控）。

## 补充：外屏可见性是平台白名单制（2026 官方渠道核实）

「外屏添加不了本应用」不是代码问题：Pura X 外屏显示三方应用需
**适配 → 上架应用市场 → 提交「外屏应用展示申请」→ 华为审核加白名单**，
本地 hdc 安装的开发版无法添加到外屏。且**外屏不支持本地真机调试**（官方问答），
外屏形态验证走 DevEco Studio 的 Pura X 模拟器。
（出处与链接：docs/harmonyos-resources.md「折叠屏与外屏适配（Pura X）」。）

对验证策略的影响：COVER 项中的「外屏触发」在模拟器上验证；真机只能验证
「小窗 / 横屏触发紧凑模式」与「折叠展开连续性」（决策不变，窗口尺寸驱动的方案
对模拟器与真机路径同样成立）。
