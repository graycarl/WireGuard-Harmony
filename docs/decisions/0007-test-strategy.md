# 0007 · 测试策略总纲：三层测试 + 真机互操作验收终点

- 状态：**已决定**（2026）
- 关联：AGENTS.md 决策 3（本地单测空桩）、[0001](0001-dataplane-self-implemented-c.md)、[0002](0002-handshake-in-native-c.md) 的可测性条款

## 背景

「开发测试完成」需要一张明确的测试地图：什么能本地测、什么必须真机、验收终点是什么。
核心约束（已核实）：**本地单测中所有 `@kit` 平台 API 都是空桩**——不抛错但返回空数据；
hypium 存在「假绿」问题（失败仍 BUILD SUCCESSFUL，须 `grep -c "Error in"` 判 0）。

## 决策内容

### 第一层：本地单测（`entry/src/test`，hypium，`make test`）

覆盖所有**不 import `@kit`** 的纯模块，目标全绿且作为提交门槛：

| 模块 | 内容 |
|---|---|
| `config/` | wg-quick 解析（含上游全部边界用例）、序列化往返、AllowedIPs 解析与路由计算 |
| `crypto/`（ArkTS 镜像） | base64/hex、BLAKE2s（含 keyed）、HKDF —— 全部过官方测试向量 |
| `repo/` | tunnels.json 序列化/diff/损坏恢复（文件 I/O 依赖注入） |
| `model/` | 状态机迁移、单激活不变量（0006） |

判定纪律：`make test 2>&1 | grep -c "Error in"` 必须为 0（Makefile 已内置）。

### 第二层：真机验证清单（平台原语薄封装）

以下能力本地无法测，逐项列清单、真机逐条打勾（清单随代码维护在 `docs/` 下）：

- cryptoFramework：X25519 协商、ChaCha20-Poly1305（仅用于 ArkTS 镜像对照，正式协议在 C 层）
- vpnExtension：授权弹窗、tun fd 获取、protect、路由下发、stop/destroy 回调
- 0004 待验证清单 4 项（进程死亡断连、系统设置关闭感知、抢占行为、后台公共事件）
- 锁屏认证（查看/导出私钥前置）

### 第三层：互操作验收（测试完成的终点）

**与上游 Linux `wg` 对端真机互通**为最终验收，用例固定为：

1. 握手建立（我方发起 / 对端发起两个方向）
2. 双向数据收发（ping + 大流量，验证计数器/nonce/重放窗口）
3. keepalive 长时在线（≥10 分钟无流量不掉线）
4. rekey（会话满 120s 闲置/计时触发重协商）
5. roaming（Wi-Fi ↔ 蜂窝切换后恢复，对应 0005 第 3 条）
6. PSK（预共享密钥）配置互通

对端拓扑：一台公网 Linux 主机跑 `wg`，配置步骤与判定标准写入 `docs/interop-testing.md`（随数据面开发时补）。

### C 层自测

- 密码原语 KAT：构建期/启动期自检（官方测试向量编译进 `.so`，启动校验失败即拒绝启动并上报）。
- 条件允许时为 cpp 建 host 侧独立测试目标（CMake + 本机编译跑协议状态机单测），
  列为增强项，不阻塞主线。

## 后果

- 每段代码从落笔起就知道自己属于哪一层、怎么被验证；不会出现「写完了才发现没法测」。
- 互操作验收是硬终点：六条用例未全绿前，项目不视为「测试完成」。
