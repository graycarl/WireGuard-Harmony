# 0002 · 握手协议（Noise IK）放 C 原生层，ArkTS 纯控制面

- 状态：**已决定**（2026）
- 关联：[0001 数据面自研 C](0001-dataplane-self-implemented-c.md)、AGENTS.md「核心设计决策 1/3」

## 背景

WireGuard 握手是 Noise IK 框架的实例化：X25519 两次 DH + BLAKE2s 链式哈希/HKDF 派生 +
ChaCha20-Poly1305 加密静态公钥与时间戳，外加 cookie 机制（可选的 DoS 缓解）。
0001 已确定数据面在 C 层自研，握手放哪一层需要单独定：它既是「协议逻辑」
（倾向靠近数据面），又含「纯算法」（按决策 3 倾向放 ArkTS 以便本地单测）。

## 候选方案与取舍

| 方案 | 结论 | 理由 |
|---|---|---|
| **A. 握手放 ArkTS 控制面**（BLAKE2s 自实现可本地测；X25519/ChaCha20 薄封装 cryptoFramework；派生出的会话密钥经 NAPI 下发给 C 数据面） | ❌ 否决 | ① **本地可测性是假象**：X25519 与 ChaCha20-Poly1305 在本地单测中是空桩（决策 3 已核实），完整握手流程在本地永远跑不通，能测的只有 BLAKE2s/HKDF 两个零件——这两个零件放哪层都能镜像测。② **协议重复**：C 数据面已必须有全套四个原语（传输加密用），ArkTS 再实现/封装一份 = 同一算法两份实现、两倍的 KAT 维护面。③ **热路径跨界**：重协商由发包路径触发（发送时无有效会话/rekey 超时），握手在 ArkTS 意味着 C 数据面热路径要经 NAPI 上抛再下传，增加时延与状态一致性风险。 |
| **B. 握手放 C 原生层**（与传输层同进程同语言，密钥就地派生就地使用） | ✅ **选用** | 四个原语只实现一份；握手状态机、定时器、发包触发重协商全部内聚在数据面；NAPI 接口保持「配置下发 / 事件上抛」的薄控制面语义；与上游 GoBackend「协议全在一个进程内」的结构同构。 |

## 决策内容

1. **分层**：
   - C 层（`entry/src/main/cpp/`）：握手状态机（initiation/response/cookie）、会话密钥派生与轮换、
     全部定时器（rekey/reject-after/keepalive/握手重试）、传输加解密、tun↔UDP 转发。
   - ArkTS 层：wg-quick 解析、配置持久化、隧道生命周期控制、状态展示。**不含任何协议逻辑**。
2. **NAPI 接口语义**（薄控制面，协议细节不外泄）：
   - 下发：`start(tunFd, {私钥, listenPort, peers[{公钥, presharedKey?, endpoint, allowedIPs, keepalive?}]})`、`stop()`、配置更新。
   - 上抛：握手成功/失败事件、最新握手时间、rx/tx 字节统计、对端 endpoint 实际地址（ roaming 后）。
3. **v1 范围**：cookie 机制（message type 3，DoS 缓解）**标记为可选、v1 不实现**——
   协议上 cookie 是对端受压时才启用的可选优化，不实现不影响正常互操作；
   若互操作测试遇到高负载对端再补。
4. **可测性保障不削弱**：
   - BLAKE2s/HKDF 的 ArkTS 镜像实现 + 官方测试向量照常进本地单测（验证的是算法理解，
     作为 C 实现的对照）；
   - C 层原语在构建期跑 KAT 自检（启动时或独立 host 侧测试目标）；
   - 握手正确性的验收终点不变：**与上游 Linux `wg` 对端真机互操作**（含 roaming、rekey、keepalive 场景）。

## 后果

**正面**
- 协议实现单点化：一套原语、一个状态机、一处定时器，无跨语言协议状态同步问题。
- NAPI 边界干净：跨边界的只有配置与事件，频率低、结构稳定，易于长期维护。
- 与 0001 自然衔接，决策链闭合。

**负面与缓解**
- 握手逻辑脱离本地单测覆盖 → 缓解：KAT 兜底原语、互操作测试兜底协议；
  排查手段上预留 C 层详细握手日志（hilog）开关，真机调试期常开。
- ArkTS 侧无人「看得懂」协议细节 → 缓解：cpp 目录内补一份握手流程注释/状态图
  （对照上游 `device.go`/`noise-*.go` 结构），降低后续维护门槛。

## 回溯条件

仅当互操作测试证明 C 层握手实现存在系统性偏差且久查不出时，才重新评估方案 A；
届时 ArkTS 侧已具备的 BLAKE2s/HKDF 镜像实现可直接复用，迁移成本可控。
